1. 事件序列模型

  • 一个手势 = DOWN → MOVE… → UP/CANCEL；DOWN 定归属，序列内不换人
  • 事件跟着归属走，不跟着位置走
  • 滑出屏幕 → 系统发 CANCEL；从屏幕外滑入 → 发全新 DOWN（新序列）

2. 三大方法

  • dispatchTouchEvent：总调度，View/ViewGroup 都有
  • onInterceptTouchEvent：仅 ViewGroup，派发前抢票，只在 DOWN 或已有 target 时被询问
  • onTouchEvent：真正干活，返回值 = enabled && (clickable || longClickable)

3. mFirstTouchTarget 归属链

  • 节点三元组：child（谁当班）+ pointerIdBits（负责哪几根手指，位图）+ next
  • 为什么链表不是 List<View>：归属粒度是手指不是 View，同一 View 多指合并成 1 节点；节点数 = 正在消费的不同子 View 数
  • 四阶段：① 空闲 null → ② 建立（DOWN 消费成功）→ ③ 中途拦截（CANCEL+摘链）→ ④ 自然结束（UP 清链）
  • 增删：增=addTouchTarget 头插；删=clearTouchTargets（UP）、cancelChild（拦截摘单个）、removePointers（POINTER_UP 减位图）

4. 拦截机制

  • action==DOWN || target!=null 为什么是 ‖：&& 会把 DOWN 踢出拦截判断 → 恒自吞 → 子 View 永远收不到事件
  • 无 target 时 intercepted=true 直接赋值：无对象可抢，调回调纯浪费；true = "无处可去、必然由我接管"
  • 拦截完整链路：拦 → 给旧 target 发 CANCEL → 摘链 → 自己走 child=null 分支接管（下一拍生效）

5. CANCEL 语义

  • UP = 正常完成（触发 performClick）；CANCEL = 被外部夺走（不触发 click）
  • 拦截改发 UP 的两个 Bug：滚动误触点击、子父状态错乱
  • Button 收到 CANCEL：setPressed(false) + removeLongPressCallback()，绝不 performClick

6. 禁拦令

  • requestDisallowInterceptTouchEvent：逐层上传；每个 DOWN 被 resetTouchState 清除（新手势必须重设）；一拍延迟
  • cancelAndClearTouchTargets 管"人"（发 CANCEL+清链）；resetTouchState 管"开关"（清禁拦令、嵌套滚动轴）

7. 滑动冲突两套解法

  • 外部拦截法（父主导）：RecyclerView 状态机——DOWN 放行重置基准；MOVE 破 touchSlop 且 canScroll 才拦；拦后锁定；POINTER_UP 切基准手指
  • 事后盖章：scrollByInternal 真滚了才设禁拦令，不在 DOWN 提前占座
  • 内部拦截法（子主导）：DOWN 设禁拦 → MOVE 让权则解禁；必须 return super.dispatchTouchEvent
  • return true = 有名无实（内部没建链）；return false = 不声称也不实干；return super = 实干+如实上报
  • super 的语义：调父类(ViewGroup)的方法处理自己的子树，方向向下；类的爸爸 ≠ 视图的爸爸

8. 经典场景

  • item 不可点：RV 空链自当大 View 直接滚；item 可点：链建 item 上，破 slop 拦截+CANCEL；轻点触发 click / 拖动滚动优先
  • ViewPager+横向 RV：让权=父 onIntercept 全程 false、RV 滚到底；拦截=某拍父 true → RV 收 CANCEL → 父 onTouchEvent 接管；父在 UP 也会被问一次

9. 陷阱清单

  • ‖ 改 && → 子 View 收不到事件
  • return true 不 return super → MOVE 断层
  • super 误当父 View
  • 拦截时发 UP 不发 CANCEL → 误触 click
  • 禁拦令设一次不管 → DOWN 会清零
  • 无 target 期待 onIntercept 被调 → 不会
